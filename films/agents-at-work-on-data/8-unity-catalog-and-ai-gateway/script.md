## The promise

Every line passes two tests: someone who has never opened a data platform can follow it, and a platform engineer or a security lead finds nothing wrong in it. *Working with agents on Databricks* gave every agent the same governed data and tools people use, and left one question: when an agent reads on its own, whose reads are they, and who pays for its model? This film answers it. An agent that runs on a person's own key gets everything that person can do, its model calls come from no one's budget, and the log can't tell its reads from hers. Given a name of its own, a service principal, an agent sits under the rules people already work under, kept where the data and the models live: in Unity Catalog, the same grants to its group, the same masks and row filters, its tools as functions it may run and can't change, and its reads in the log and in lineage; in Unity Gateway, part of the catalog, the models and tool servers it may call, checks on what goes in and out, a limit on how fast it calls, and every call counted under its name. A rule an agent is told is a request; a rule the platform enforces holds, whatever the agent is told. **One set of rules for people and agents, enforced where the data and the models live.**

## The story in one paragraph

Today, at the university. Every week, the faculties send the registrar's office the same questions: how many students, in which courses. So Mei Tanaka set up an agent that answers them at night, on its own, in an afternoon, with her personal key, so it acts as her. Each month, Sam Okafor, who runs the data platform, checks the log of who read the learner table, with every learner's name and email: one Sunday night, Mei read it 2,300 times. She was asleep; the reads were her agent's. Acting as her, it could read everything she can, though all it needed was counts; a cleverly worded question could have tricked it into handing names over; its model calls ran on a key of hers, from no one's budget, and no one saw what they carried; and if names ever leaked, the log would point at Mei. She did nothing wrong: a personal key can't hand over less than everything she has. Something had to change. So Sam gives the agent a name of its own, under the same rules as people: Unity Catalog gives it only the grants its job needs, and stars where the names are; Unity Gateway lets it call only the models it's allowed, and counts what it spends. It worked: the faculties get the same answers every morning, the agent hasn't seen a single name since, its calls cost about 300 dollars a month from the registrar's own budget, and the log says whose reads they were. Jun's census agent works the same way. Then the film asks why both: the project's page for agents already says never to copy names into a prompt, but a rule an agent is told is a request it can misread, lose or be talked out of, while a rule the platform enforces holds. It shows the two places that keep the rules (Unity Catalog for what agents touch, Unity Gateway for the models and tool servers they call); a name for the agent, a service principal in a group, with its group's grants, which Sam can switch off without stopping anyone else, and Mei still its owner; the same policy that shows Clara stars showing the agent stars, because the account's users include every service principal, the same for a row filter, and the learner code readable for counting, so Jun's agent checks 18,412 students without a single name; its tools as a function Mei's office owns and tool servers registered in the catalog, each granted like a table; its models as services only those granted can call, with checks in beta that hide an email address in a prompt or look for words written to trick it, a limit on its calls, and every call counted under its name; and Sam's log a month later, where Mei's reads and the agent's are apart, with lineage and the gateway's own table beside it. Rules kept there hold for every agent, every tool and every person, and they're the rules people already work under: one set to keep, one log to read, one review. The number the university sends the government is checked by an agent the team can see, limit and account for.

**Where the film adopts, extends or differs.** It adopts the platform's model as its docs give it: one catalog that governs data, functions, models and tool servers by the same grants. It extends it with the module's rules from practice: tool servers get the fewest rights (the registrar agent's only read), an agent always has a human owner, and nothing reaches production without a person. It differs from a reading of the docs that would make the agent's instructions enough: the project's page for agents still tells it the rules (*An agent on the team*), and the film says to do both, tell the agent and enforce the rules where the data and the models live.

**Practice, from the author (the plan's insights):** an agent in the wrong hands is more dangerous; tool servers get the fewest rights, read only when reading is enough, and no sensitive data; memory and context are shared by the team (the next film); agents are never approvers. A practitioner will recognise the opening: an agent built in an afternoon on someone's personal token, which works, and which nobody can see apart from the person whose token it is. Databricks itself calls personal access tokens a legacy way to sign in and recommends OAuth "because OAuth provides stronger security".

**What the film leaves to its siblings and the later series.** How an agent earns its own identity, step by step, with a GitHub App and no secret, is *From helper to colleague*'s (its *An agent with its own badge*); watching each agent's work and cost on one page, with a budget that stops it, is *A colleague that isn't a person*'s. Masks and groups for people are *Governed in Unity Catalog*'s, and are recalled, not taught. The team's context and memory, governed, is the next film's.

## Sound

No other film on the site uses either; no maker is named. Both are made in the film's own `tools/score.py` and low-passed, so nothing rings above about 2.5 kHz.

## Rigour to check before recording

Checked on 4 November 2026 on docs.databricks.com (AWS); the sources are listed below. Product names and maturity are the docs' on that day.

- **Unity Gateway, not AI Gateway.** Databricks' release notes for Unity Gateway, 4 August 2026: "Unity Gateway is now generally available. Unity Gateway is the Databricks governance solution for enterprise AI, part of Unity Catalog." and "Some capabilities, including service policies and agent services, remain in Beta." The AI governance guide: "Unity Gateway and Unity Catalog asset governance are generally available. Service policies are in Beta". The name "Unity AI Gateway" is from a community post of 22 May 2026, while it was in beta, and no doc page on the day uses it; the workspace's sidebar still says "AI Gateway". The plan's working title said "AI Gateway"; the film says "Unity Gateway", once glossed as "its gate to models", and the folder keeps its name, `8-unity-catalog-and-ai-gateway`.
- **"Her personal key, so it acts as her."** Databricks, *Authenticate with Databricks personal access tokens (legacy)*: a token is "for the Databricks user account or Databricks service principal"; without a scope it grants "full workspace access (the `all-apis` scope)"; scopes "restrict a token's permissions to specific API operations", not to tables, so through SQL it still reads what its owner can; "Where possible, Databricks recommends using OAuth instead of PATs for user account authentication because OAuth provides stronger security." The film's "a personal key can't hand over less than everything she has" means her data: no token she makes can read less than she can. "Databricks automatically revokes PATs that haven't been used for 90 days": a key an agent uses every night never lapses.
- **The log.** `system.access.audit`, in Public Preview, keeps a year; a read is a `getTable` event (the project's `docs/databricks-governance.md`, section 6, and `analyses/governance/who_read_a_table.sql`, which selects `event_time, user_identity.email` for the learner table this month). Reads made with Mei's token are hers in the log; the film's "2,300 times" on one Sunday night is invented and small for an agent that answers a week's questions with several queries each. - **Service principals.** *Service principals*: "You can grant and restrict a service principal's access to resources in the same way as you can a Databricks user", and it can be added "as a member to a group". *Manage service principals*: "You can deactivate a service principal at either the account or workspace level. Deactivation prevents the service principal from authenticating and accessing Databricks APIs, but does not remove its permissions or objects", and "When reactivated, the service principal regains access with the same permissions." The film's "switches off its service principal" is deactivation. The project's `AGENTS.md`: "On Databricks, you work as your own service principal, never as a person. - **Grants go to groups.** *Governed in Unity Catalog*: "Who may read a table is a grant, and a grant goes to a group, never to a person"; the project's section 8 grants each product to a readers' group. The film's "As for people, its grants go to its group, never to the agent alone" is the same rule.
- **The same masks.** The project's section 3 creates `mask_direct_personal_data` "on catalog …, with the mask, to `account users` except the readers". *Groups*: "Each account includes an `account users` group containing all users and service principals." ABAC's policies page: "The `TO` clause specifies the users, groups, or service principals subject to the policy." - **Functions as tools.** *Create a custom tool*: "Use Unity Catalog functions when your agent needs to run predefined logic", and "calling an existing function requires `EXECUTE` on it". The AI governance guide: "Unity Catalog also governs the functions that agents use as tools, with the same privileges." Changing a function takes its ownership (or `MANAGE`), which the agent's group doesn't have. `count_students` is the film's, the registrar's office's; the film doesn't claim whose privileges its body runs with.
- **Tool servers.** *Govern an MCP*: external MCP servers are registered as Unity Catalog MCP services; "Callers need `EXECUTE` on the MCP, `USE CATALOG` and `USE SCHEMA` on its parents". - **Models.** *Model services*: "By default, only the model service owner can query it. - **Checks, in beta.** *Service policies for AI securables* (Beta, page updated 29 October 2026): built-in policies under `system.ai`, among them `system.ai.detect_sensitive_data`, which "detects structured sensitive data (such as credit card numbers and Social Security numbers) and either blocks the interaction or redacts the matched values", and `system.ai.block_jailbreak`, which "detects jailbreak and prompt-injection content", and on MCP services "can evaluate the tool call and arguments on input, the tool result on output, or both". *Detect sensitive data* (Beta, updated 19 October 2026) lists 15 categories, among them `class.email_address`; "Names, locations, and organizations" are not detected. The film's "Lineage shows the tables its queries read" is a read event's lineage. `core_enrolment` and `core_course` are drawn as the core tables an answer about a course would read.
